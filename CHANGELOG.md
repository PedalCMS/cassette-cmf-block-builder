# Changelog

All notable changes to this project are documented in this file. The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/). Before 1.0, a minor release may contain breaking changes; each one is listed under "Breaking" with a one-line migration note.

## [Unreleased]

Prepared for release `0.2.0`. The maintainer turns this heading into `## [0.2.0] - <date>` when tagging.

> **Do not use tag `v0.0.1` with `pedalcms/cassette-cmf` 0.1.1 or newer.** `v0.0.1` imports the old `Pedalcms\CassetteCmf\...` namespace casing, its `^0.1` constraint allows cassette-cmf 0.1.2, and Composer's classmap is case-sensitive, so the pair fatals with class-not-found. Use `0.2.0` or newer of this library, which requires `pedalcms/cassette-cmf: ^0.2.0`.

### Security

- **Closed an information disclosure in the `cassette-cmf/field` block bindings source.** Any site that loaded the library registered this source, and it passed the block author's `field`, `context` and `context_type` straight to `CassetteCMF::get_field()`. A contributor (whose draft preview renders blocks), or an author of a published post, could bind a `core/paragraph` to any option (`context: "mailserver", field: "pass"` reads the option `mailserver_pass`) or to any post's meta, including protected `_` keys and meta of private or draft posts, and the value was printed. Now:
  - the source is only registered when the consumer opts in (see Breaking);
  - a value resolves only for a field that is registered with cassette-cmf **and** marked `bindings: true`; unregistered or unmarked fields, and `password` / `secret` fields, never resolve; the option name or meta key is never built from the block author's input;
  - protected meta is refused even for a marked field; a post that is not publicly viewable also requires `current_user_can( 'read_post', $id )` of the current user (for an explicit `context` post ID and for the block's own context post alike); password-protected posts are refused;
  - the new `cassette_cmf_blocks_binding_allowed` filter can only narrow these rules;
  - every refusal returns `null`, so core keeps the block's saved content.

  **Advisory.** Affected: every site running a release of this library that registers the source (`v0.0.1` and every `main` build before this release) together with any user who can write a block's `metadata.bindings` (contributors and above). Impact: read access to arbitrary options and post/term meta values, including secrets kept in options and the meta of private posts. Fix: upgrade to this release. Workaround: none needed for sites that do not use bindings (the source is no longer registered at all); sites that do use bindings must upgrade and mark the fields they expose.

### Breaking

- **The `cassette-cmf/field` bindings source is now opt-in.** Migration: call `CassetteCMFBlocks::boot( [ 'bindings_source' => true ] )` before `register_from_*()`.
- **Only fields marked `bindings: true` resolve.** Migration: add `'bindings' => true` to each cassette-cmf field config that a binding reads. This needs `pedalcms/cassette-cmf` 0.2.0 or newer (it adds the key and `CassetteCMF::is_field_public()`); with an older version nothing resolves and the source returns `null`.
- **A field config that declares `binding.source: 'cassette-cmf/field'` while the source is disabled now triggers `_doing_it_wrong()`** when the block compiles. Migration: boot with `bindings_source => true`.
- **`Compat\Requirements::MIN_CMF_VERSION` is raised to `0.2.0`, and `composer.json` now requires `pedalcms/cassette-cmf: ^0.2.0`** (the release that has `CassetteCMF::is_field_public()` and `php >=7.4`). Older cassette-cmf releases fatal on the namespace rename or lack the bindings helpers; the guard turns that into an admin notice. Migration: use cassette-cmf 0.2.0 or newer.
- **A field with `source: 'context'` must now name its block-context key in `context`.** Before, `source: 'context'` was recognised but did nothing. Migration: add `'context' => 'vendor/key'` (a non-empty string); a block with such a field and no key is no longer registered (`_doing_it_wrong()`; the JSON validator reports it too). The key is added to `usesContext` automatically.
- **`unique` is now validated.** It was documented as "not implemented" and silently ignored. Migration: use `true` or `{ scope: 'post' | 'ancestor', block?, key? }` on a `text`, `email` or `url` field; a malformed setting, or `unique` on any other control type, makes the block fail to register (`_doing_it_wrong()`).
- **Every control type now has a server sanitizer.** Controls that have no `cassette-cmf` field type (`rich_text`, `code`, `icon`, `link`, `box`, `spacing`, `border`, `border_box`, `shadow`, `angle`, `alignment_matrix`, `toolbar_align`, `unit`, `letter_spacing`, `font_size`, `font_family`, `font_appearance`, `line_height`, `duotone`, `image_size`, `key_value`, `options_list`, `media_gallery`, `entity_select`, `post_select`, `term_select`, `user_select`, `taxonomy_select`, `sibling_field`, `conditions`, `query_builder`) used to reach `sanitize_attributes()`, `render.markup`, `render.callback` and `render.template` exactly as stored. They are now cleaned to the shape the editor control stores (for example `rich_text` through `wp_kses_post()`, `link` to `url` / `title` / `opensInNewTab` / `id` / `type` / `kind` with `url` through `esc_url_raw()`, CSS values against strict patterns, entity pickers to positive integers); a value of the wrong shape becomes the field's `default`, else the empty value of its JSON type. The full table is `docs/STABILITY.md` section 4. Migration: if a custom render callback relied on receiving a raw value (for example extra keys in a `link`, a length such as `calc(...)` in a `box` side, or a `code` / `rich_text` value that `wp_kses_post()` would change), check what it receives now; a control type you register yourself without a `cmf_type` is still not sanitized.
- **The `shadow` control's attribute is now a string.** It was declared as an `object` although the control, the documentation and the stored value are a CSS `box-shadow` string, so WordPress dropped every saved value. Migration: none for stored content (a string now validates); code that read the attribute as an array should read a string.
- **`prefix` is a required boot option.** `CassetteCMFBlocks::boot( [ 'prefix' => 'acme' ] )` (`^[a-z][a-z0-9-]{1,30}[a-z0-9]$`) derives every identifier two copies of the library could share. Without a valid prefix (including `register_from_*()` / `init()` before `boot()`) a `_doing_it_wrong()` notice is raised and the fallback `cassette-cmf` is used (so the derived names are `cassette-cmf-blocks-editor`, `cassette-cmf-blocks/v1` and `cassette-cmf/field`). Migration: add `boot( [ 'prefix' => '<your-plugin>' ] )` before `register_from_*()`.
- **The editor script and style handles are renamed** from `cassette-cmf-block-builder-editor` / `cassette-cmf-block-builder-editor-style` to `{prefix}-blocks-editor` / `{prefix}-blocks-editor-style`, and `Asset_Loader::HANDLE` / `STYLE_HANDLE` are removed (use `Core\Identity::editor_script_handle()` / `editor_style_handle()`). Migration: depend on the new handle (for example `acme-blocks-editor`).
- **The REST config route moved** from `/cassette-cmf-block-builder/v1/config` to `/{prefix}-blocks/v1/config`. Migration: call the new URL (`Identity::rest_namespace()` in PHP).
- **The block bindings source is renamed** from `cassette-cmf/field` to `{prefix}/field`, and `Binding_Source_Registrar::SOURCE_NAME` is removed (use `Identity::binding_source_name()`). Migration: change `metadata.bindings.*.source` in saved content and in patterns, and any `binding.source` in field configs, to `{prefix}/field`.
- **The editor JS global is renamed** from `window.cassetteCmfBlocks` to `window.cassetteCmfBlocks_{camelPrefix}` (`my-shop` gives `myShop`). The extension points `registerControlType`, `registerMigration` and `registerIdInUseCheck` now live on that per-prefix object. Migration: `window.cassetteCmfBlocks_acme.registerMigration( ... )`.
- **Unknown `args` keys are no longer passed to `register_block_type()`.** `args` is now checked against an allow-list (every key the docs map or mention, plus the new asset keys; see `docs/block-config-reference.md`); anything else raises `_doing_it_wrong()` naming the key and the block, and is dropped. Before, any key reached `register_block_type()` verbatim, so snake_case spellings such as `view_script_module_ids`, `view_style_handles` or `editor_style_handles` worked by accident. Migration: use the camelCase keys (`viewScriptModule`, `viewStyle`, `editorStyle`, `usesContext`, `allowedBlocks`, ...); `variation_callback` is still accepted as written.
- **The editor payload cache group** is now `cassette_cmf_blocks_{prefix_snake}` (the prefix is also part of the cache key); cached payloads are rebuilt once.
- **`render.deprecated[].markup` is ignored for dynamic blocks.** A dynamic block has nothing stored to validate against, so its deprecations now use the dynamic `save()` and `isEligible`. Migration: describe the old attributes with `attributes` and `migrate` (see `docs/static-save.md`). Static blocks are unchanged.
- **`Control_Catalog::register_type()` validates what it is given.** The type id must match `^[a-z][a-z0-9_]*$` and `value_type` must be `null` or one of `string`, `number`, `integer`, `boolean`, `array`, `object`; anything else throws `InvalidArgumentException` (and a malformed entry returned by the `cassette_cmf_blocks_control_catalog` filter is dropped with `_doing_it_wrong()`). Migration: rename a type whose id used capitals or dashes; replace an unusual `value_type` (such as `float`) with `number`. Only `value_type` is required now (`cmf_type` defaults to `null`, `is_container` to `false`, `holds_value` to "`value_type` is not null"), so existing four-key registrations keep working.
- **`toggle` / `toolbar_toggle` values reach render code as booleans, and `media` as an integer.** The cassette-cmf form sanitizers they reuse returned the strings `"1"` / `"0"` (single checkbox) and `""` (empty upload) for attributes the schema declares `boolean` / `integer`. `Block_Definition::sanitize_attributes()` and so every `render.callback`, `render.template`, markup tree and `cassette_cmf_blocks_render` filter now get `true` / `false` and an `int` (the field's `default`, else `0`, for an unusable value). Migration: compare with `true` / `false` (or truthiness) instead of `'1'` / `'0'`; a markup `{{ flag }}` interpolation of a false toggle prints an empty string instead of `0`; test `0` instead of `''` for an empty `media`.

### Added

- **Shortcode and raw transforms backed by a PHP callback.** `transforms.from` accepts `{ type: 'shortcode', tag, callback }` and `{ type: 'raw', selector, callback }`, where `selector` is a CSS selector string or a `{ tag, class, attrs }` rule and `callback( array|string $input, array $context ): ?array` returns `{ attributes, innerBlocks? }` or null. The editor registers real core transforms; the block is created at once with a pending marker (a loading placeholder) and filled in from `POST /{prefix}-blocks/v1/transform` (`edit_posts`; the request names a configured block and position, never a callable). The result goes through `Block_Definition::sanitize_attributes()`, inner blocks are checked against the block registry. On failure a snackbar shows the error and the original content stays (`core/shortcode` / `core/html`). The payload gains `restNamespace`. New classes: `Schema\Transform_Config`, `Rest\Transform_Controller`.
- **Drag-and-drop repeater rows** using core's `Draggable` (no new library). The Move up / Move down buttons stay for keyboard users; both paths announce "Row moved to position N of M" through `wp.a11y.speak()`.
- **`preview.when`**: a condition rule (the `conditions` shape; cross-block `{ source: 'block', ref }` rules are ignored like everywhere else) that gates the editor preview. While false, a placeholder (the block's `placeholder` texts, else "Configure this block.") replaces the markup or server-side preview, and no server preview request is made. `block-schema.json` describes `preview` and the new transform types.
- **First-class asset keys in `args`**: `editorScript`, `editorStyle`, `script`, `style`, `viewScript`, `viewStyle` and `viewScriptModule` (block.json names) map to `editor_script_handles`, `editor_style_handles`, `script_handles`, `style_handles`, `view_script_handles`, `view_style_handles` and `view_script_module_ids`. Each takes a registered handle / module ID or a list of them; invalid shapes are dropped with a notice and rejected by `Block_Schema_Validator` and `block-schema.json`. Block.json `file:` paths are not supported: register the asset yourself. They are server-side only and not sent to the editor. Tests assert the `WP_Block_Type` for both forms, the validator, the allow-list, that the library's own editor script and a consumer `editorScript` load together, and that a `viewScriptModule` is printed only on pages that render the block, on a block theme and a classic theme (fixture themes in `tests/fixtures/themes/`).
- **Server-side attribute API** (`@api`): `Block_Definition::sanitize_attributes( array $attributes ): array` (the exact pipeline the render callback runs; the renderer now calls it, so there is one copy), `Block_Definition::attribute_schema(): array` (the `attributes` passed to `register_block_type()`) and `CassetteCMFBlocks::get_definition( string $block_name ): ?Block_Definition`. PHPUnit renders a block with every value-bearing control type through `do_blocks()` and asserts the callback received what `sanitize_attributes()` returns, for valid, junk, dirty and missing input.
- `Block_Definition::allowed_arg_keys()` (the allow-list) and `Block_Definition::ASSET_KEYS`.
- Docs: `docs/wordpress-org-compliance.md` (prefixing with Strauss, no remote assets, escaping, i18n, GPL, the `readme.txt` source-code section, Plugin Check notes) and `docs/RELEASE.md`, both linked from the README; the full `args` table and the attribute API in `docs/block-config-reference.md`.
- **Coexistence.** Two copies of the library (plain or Strauss-prefixed) can load on one site and one page; see `docs/coexistence.md`. New `Core\Identity` derives the handles, REST namespace, binding source, JS global and cache group from the prefix. The `cassette_cmf_blocks_assets_url` filter gets the prefix as a second argument. The editor bundle reads its payload global from a one-shot `window.cassetteCmfBlocksBoot` hand-over, and the editor script is registered without a loading strategy so two bundles cannot interleave.
- Tests: a PHPUnit two-copies test (`Test_Coexistence`, with a Strauss-style prefix generator in `tests/Support/`) and Jest tests for the bootstrap hand-over, per-bundle registries and per-bundle instance watchers.
- `CassetteCMFBlocks::boot( array $options = [] ): Block_Manager` for boot options, called once before `register_from_*()`. Options: `bindings_source` (bool, default `false`) and, since the coexistence work, the required `prefix`. `register_from_*()` / `init()` before `boot()` auto-boots with the defaults; a later `boot()` with different options, unknown option keys and wrongly-typed values trigger `_doing_it_wrong()` and are ignored.
- Filter `cassette_cmf_blocks_binding_allowed( bool $allowed, array $source_args, WP_Block $block )`.
- `Compat\Requirements::MIN_PHP_VERSION` (`7.4.0`) with a `PHP_VERSION_ID >= 70400` check in `Requirements::check()`: where the code can still be loaded on an older PHP, the library refuses to boot and shows an admin notice (a no-op on supported PHP).
- **`uuid` field type** (`[ 'name' => 'instanceId', 'type' => 'uuid' ]`): a string instance ID with no inspector control. The editor generates a lowercase v4 UUID when a block is inserted, gives a duplicated or pasted copy (at any depth) a new one while the original keeps its own, and never changes it on load, undo/redo, transform, move or save. Blocks already in the post when the editor opens are left alone (consumers handle missing IDs). The server only validates (`Render\Attribute_Sanitizer::sanitize_uuid()`: a UUID of version 1-8 in any case, lowercased; anything else becomes `''`) and never generates one. New JS extension point `window.cassetteCmfBlocks.registerIdInUseCheck( ( id, blockName ) => boolean | Promise<boolean> )` lets a consumer veto an ID on a newly inserted or pasted block; see `docs/control-catalog.md`.
- **`source: 'context'` fields**: `[ 'name' => 'formId', 'type' => 'text', 'source' => 'context', 'context' => 'example/formId' ]` reads a value an ancestor provides with `args.providesContext`. Read-only, no attribute, nothing stored, nothing rendered in the inspector; the value is available under the field's name in markup templates, PHP templates, conditions and the live editor markup preview. `usesContext` is filled in automatically. `args.providesContext` / `args.usesContext` are verified end to end (server registration, editor payload, rendering). `examples/03-advanced-array` gains a parent `example/form` and child `example/field`.
- **`unique` on `text` / `email` / `url`**: `true` (whole post) or `{ scope: 'ancestor', block: 'vendor/form' }` (among blocks under the same nearest ancestor of that name, at any depth), with an optional `key` that groups different block types into one uniqueness check (defaults to the field name). Values are trimmed, formatted with the field's `format`, compared case-sensitively; empty values never collide. The editor shows an inline error on every colliding block except the oldest owner (saving is never blocked) and auto-suffixes a duplicated or pasted copy with the first free `-2`, `-3`, … without touching the original. The rule is a pure function in both languages (JS `findCollisions()`, PHP `Render\Unique_Checker::find_collisions()`, `@api`), tested against the shared `tests/fixtures/unique.json`, so a consumer can re-run it on saved content.
- One editor-wide instance watcher (a single debounced `core/block-editor` subscription, one O(n) pass) serves `uuid` and `unique`, and does nothing at all when no block uses them.
- Tests: bindings disclosure suite, classmap loading test, bundled-examples validation test.
- **`render.deprecated` for dynamic blocks.** An entry is `{ attributes: <old schema>, migrate: { rename, map, set, remove } | 'namedMigration', migrate_php?: callable }` (the same keys static mode uses; `markup` is not needed). The editor registers each entry as the block type's `deprecated` with an `isEligible` that fires on old-shape attributes, so stored blocks migrate when the post opens. The server runs the same declarative migration, then `migrate_php( $attributes, $entry )`, as the first step of `Block_Definition::sanitize_attributes()`, so stored old-shape markup renders with the new output without a re-save (pipeline: migrate, sanitize, conditions, render). The migration and the eligibility rule are pure functions in both languages (`Render\Deprecation_Migrator`, `migrate.js`), tested against the shared `tests/fixtures/deprecations.json`. A declarative `migrate` object is accepted in static mode too. `Block_Schema_Validator` checks the shape. See `docs/static-save.md`.
- **`ancestor_field` control.** Picks another block by its `name` attribute among the descendants of the nearest `ancestor` block (`ancestor`, `blocks`, `has_attribute`, `name_attribute`, `label_attribute`, `exclude_self`). Stores the name (string), never a clientId; live as blocks are added, renamed or removed; a vanished value shows as `missing: <name>` and is kept. Server: string attribute, plain text sanitize. `Schema\Ancestor_Options` (`@api`) validates and canonicalizes the options.
- **Cross-block `conditions` rules.** A `conditions` rule may be `{ source: 'block', ref: '<name>', operator, value? }` next to the unchanged `{ field, operator, value? }`. The control's "Compare: another block" choice appears when the field sets `conditions: { ancestor: ..., ...same options as ancestor_field }`. The builder does not evaluate such rules: `Conditional_Evaluator` and `conditions/evaluate.js` ignore them (new fixtures in `tests/fixtures/conditions.json`); `Conditional_Evaluator::is_cross_block_rule()` is `@api`. The emitted shape is documented in `docs/control-catalog.md`.
- **Placeholder area and variation picker.** Fields with `area: 'placeholder'` render inside a core `<Placeholder>` while the block is unconfigured (block-level `placeholder: { when?, label?, instructions?, icon? }`; default: every required placeholder field is empty), then move to the inspector. A block whose `args.variations` include `scope: ['block']` variations shows the block variation picker (`BlockVariationPicker` when the editor exports it, else `__experimentalBlockVariationPicker`) while it is empty; choosing one applies its `attributes` and `innerBlocks`. `Variation_Registrar` validates `scope` and `innerBlocks`.
- e2e fixture blocks `acme-e2e/form-rule`, `acme-e2e/embed`, `acme-e2e/columns`, `acme-e2e/legacy-note` and Playwright specs `ancestor-field`, `placeholder`, `dynamic-deprecation`.
- **`docs/STABILITY.md`: the 1.0 stability promise** (attribute-schema mapping, render pipeline order, sanitizer outputs per type, the `@api` PHP surface, the JS extension points, the emitted `conditions` JSON, `unique` rules, uuid rules, identity derivation, what is not frozen, the semver rule), linked from the README.
- **Custom controls are a public, stable extension.** `Control_Catalog::register_type()` / `get_type()` / `has_type()` / `get_registered_types()` and the JS `registerControlType( type, Component )` (component props `{ field, value, onChange, type }`) are documented in `docs/control-catalog.md`; `registerMigration()` and `registerIdInUseCheck()` are documented alongside. `@api` tags added to the facade (`boot`, `init`, `register_from_array`, `register_from_json`) and to `Block_Manager::boot()` / `get_option()` / `register_from_*()`.

### Changed

- Release tooling: the release workflow now accepts `-alpha.N`, `-beta.N` and `-rc.N` tags (and marks them as pre-releases), rebuilds the editor bundle and fails if the committed `src/assets/build/` differs, builds the archive from `.distignore` and includes `languages/`. `bin/set-version.sh` also updates `package-lock.json`.
- A `shortcode` / `raw` entry in `transforms.from` that has no callable `callback` (or no `tag` / `selector`) now makes the block fail to register with `_doing_it_wrong()`; these types used to be silently ignored.
- **PHP floor lowered to 7.4** (`composer.json` `require.php >=7.4`; README "Requires PHP: 7.4", "Requires at least: 6.8"). The WordPress floor stays 6.8. `array_is_list()` is polyfilled by WordPress >= 6.5.
- phpcs now runs PHPCompatibilityWP (`testVersion 7.4-`); CI gains a PHP 7.4 x WP 6.8 PHPUnit cell and a PHP 7.4 `php -l` job. The 7.4 cell cannot resolve until a cassette-cmf release declaring `php >=7.4` (cassette-cmf 0.2.0) is tagged, because cassette-cmf 0.1.2 requires `php >=8.2`.
- **Fields in the `placeholder` area are now rendered** (they used to be accepted and silently not shown anywhere): in a `<Placeholder>` while the block is unconfigured, in the inspector afterwards. A block that already used `area: 'placeholder'` will start showing them.
- `Variation_Registrar` drops a malformed `scope` (not a list drawn from `block`, `inserter`, `transform`) or a non-list `innerBlocks` with a `_doing_it_wrong()`, keeping the variation.
- `Block_Definition::sanitize_attributes()` (and so the render callback) now starts with the dynamic `render.deprecated` migration; blocks that declare none are unaffected.
- The editor payload gains a `placeholder` key per block, and `render.deprecated[].migrate` may be an object.
- **The JS extension points now work from a script that runs before the editor bundle.** `registerControlType()`, `registerMigration()` and `registerIdInUseCheck()` used to exist on the payload global only after the bundle had run, which made `registerMigration()` unusable (deprecations are built when the bundle registers the blocks). The inline "before" script now installs queueing stubs and the bundle replays the queued calls before registering any block. Scripts that call them after the bundle keep working. The registries ignore malformed registrations (a control type id that is not `^[a-z][a-z0-9_]*$`, non-function components) and are safe against `__proto__` / `constructor` ids. `Asset_Loader` gains the public constants `EXTENSION_POINTS` and `PENDING_KEY`.

### Fixed

- **`shadow` values were discarded by WordPress** because the attribute type was `object` while the value is a string (see Breaking).
- **A `uuid` field showed a "uses control type uuid, which the editor doesn’t render yet" warning in the inspector.** It is documented to render no control and no notice; found by the first real Playwright run. The field now renders nothing.
- **`options` given as a list of `{ value, label }` objects** (natural in JSON, used by `examples/02-simple-json`) produced `enum: [0, 1]` and made the select sanitizer reject real values such as `"info"`. `options` is now normalized once, when the block compiles, into the `value => label` map (both shapes accepted; anything else raises `_doing_it_wrong()`), so the attribute schema, the sanitizer and the editor payload agree.
- **`checkbox_group` with `options`** put the allowed values in a top-level `enum` on an array attribute, which WordPress compares with the whole array and so rejects every real selection. The values now go in `items.enum`.

- Markup-rendered blocks fataled on WordPress 6.8 ("Trying to access array offset on null") when `Markup_Renderer` ran outside a real `WP_Block::render()`, because `get_block_wrapper_attributes()` reads `WP_Block_Supports::$block_to_render`. It now falls back to a plain open tag when no block is being rendered. Production rendering and the block-renderer REST preview go through `WP_Block::render()`, so they were not affected; the bug showed when calling `Block_Renderer` / `Markup_Renderer` directly (tests, custom callers).
- `examples/02-simple-json/config.json` failed its own validation (`conditional.rules is required`) and threw on `init`; its conditional now uses the documented `{ "rules": [ ... ] }` shape. A test now validates every bundled `examples/*/config*.json`.
- Docs: `examples/04-advanced-json` reuses `03-advanced-array`'s block IDs, so the two cannot load together; its README now says so.
